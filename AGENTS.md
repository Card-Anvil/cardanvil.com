# AGENTS.md

Guide for coding agents working in this repo. Humans should read [README.md](README.md) first —
this file covers the conventions an agent needs and does not repeat the architecture write-up.

## What this is

The marketing and download site for [Card Anvil](https://github.com/Card-Anvil/Card-Anvil). It is
a **client-only** Vite SPA — React 19 + TypeScript, TanStack Router file routes, Chakra UI v3 —
prerendered to static HTML at build time and served from GitHub Pages. There is no SSR and no
TanStack Start; `dist/` is plain static assets.

## Commands

## Layout

| Path                  | Contents                                                  |
| --------------------- | --------------------------------------------------------- |
| `src/routes/`         | TanStack Router file routes; `__root.tsx` is the layout    |
| `src/components/`     | Page and layout components                                 |
| `src/components/ui/`  | Chakra provider and snippets                               |
| `src/theme.ts`        | Chakra system config and `globalCss`                       |
| `src/prerender.tsx`   | Build-time render entry, run in Node                       |
| `src/document-title.ts` | Title resolution shared by prerender and client           |

`src/routeTree.gen.ts` is generated by the router plugin — never edit it.

## Conventions

- **Chakra UI v3.** Use Chakra components and theme tokens rather than raw CSS. The
  `chakra-ui-builder` and `chakra-ui-refactor` skills and the `chakra-ui` MCP server are the
  sources of truth — v2 patterns do not apply.
- **Biome** handles lint, format, and import sorting: tabs, double quotes. Run `npm run check`.
- **Prerender safety.** Anything that runs during module import must work in Node with no DOM.
  New pages are discovered by crawling links from already-prerendered HTML; a page that nothing
  links to needs an entry in `additionalPrerenderRoutes` in `vite.config.ts`.
- **Page titles** come from each file route's `head()` — not from `document.title` calls.
- Imports use the `@/*` alias for anything outside the current folder, not deep relative paths.
  (`#/*` resolves to `./src/*` as well, but the codebase uses `@/*`.)

## Before you commit

`npm install` installs a husky pre-commit hook that runs what CI runs, minus the slow steps:
lint-staged fixes and formats the staged files with Biome, then `npm run sync:agents:check`
confirms the generated agent config still matches its source. The tests and the build stay on
the PR.

To commit past it — a work-in-progress commit on a branch, say — use `git commit --no-verify`.
CI still has the final word.

## Commits and branches

This repo uses [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/):

```
<type>(<optional scope>): <description>
```

Types: `feat`, `fix`, `chore`, `docs`, `refactor`, `perf`, `test`, `build`, `ci`, `revert`.
Breaking changes get a `!` before the colon (`feat(routes)!: …`) or a `BREAKING CHANGE:` footer.
Scope the area touched — `routes`, `prerender`, `theme`, `meta`, `ci`, `deps`:

```
feat(routes): add download page
fix(prerender): include styles in prerendered HTML
chore(deps): bump chakra to 3.36
```

Subjects are imperative, lower case, no trailing period. History before this convention was
adopted is not retroactively formatted — match the convention going forward.

The default branch is **`main`**; pull requests target `main`. Merging to `main` deploys to
GitHub Pages via the `pages` workflow.

## Agent configuration

Configuration is written once and fanned out, so every agent sees the same servers and skills.

**Canonical — edit these:**

| Path              | Purpose                                                |
| ----------------- | ------------------------------------------------------ |
| `AGENTS.md`       | This file. The single instruction set for every agent. |
| `.mcp.json`       | MCP servers, in Claude Code's schema.                  |
| `.agents/skills/` | Vendored agent skills, pinned by `skills-lock.json`.   |

**Generated by `npm run sync:agents` — do not edit:**

| Path                 | Consumer                                                       |
| -------------------- | -------------------------------------------------------------- |
| `.cursor/mcp.json`   | Cursor                                                         |
| `.vscode/mcp.json`   | VS Code / GitHub Copilot                                       |
| `.codex/config.toml` | OpenAI Codex (needs the dir trusted in `~/.codex/config.toml`) |
| `.claude/skills/`    | Claude Code, which only reads `.claude/skills` (gitignored)    |

**Pointers to this file:** `CLAUDE.md` (Claude Code does not read `AGENTS.md` natively) and
`.github/copilot-instructions.md`. Cursor, Codex, and the Copilot coding agent read `AGENTS.md`
directly.

After editing `.mcp.json` or updating `.agents/skills/`, run `npm run sync:agents` and commit the
regenerated files. CI runs `npm run sync:agents:check` and fails if they drifted.
